# Open questions — SKY-1 UI test cases (2026-11-15)

Found while generating and verifying UI test cases for SKY-1 «Оператор бачить відмову через комендантську годину в зоні KBP-CTR-3» with `/ui-test-case-creator` and `tc-verifier`. None of these can be settled from the SkyPermit Docs space; each blocks or weakens a test case.

## 1. Which actions does the request detail view show per state? (04)

- **Gap:** [04 — Frontend Spec › Operator portal](https://dragan1925.atlassian.net/wiki/spaces/SD1/pages/393438) lists the request detail view but not which actions (Check before submitting, Submit, Cancel) are visible in each state. [02 — State Machine](https://dragan1925.atlassian.net/wiki/spaces/SD1/pages/131074) only says illegal transitions (e.g. `REJECTED` → anything) return `409` at API level.
- **Code today:** Check/Submit are rendered only in `DRAFT`; Cancel only in `DRAFT`, `UNDER_REVIEW`, `APPROVED` (`../skypermit/components/FlightRequestPanel.tsx:22,109-118,157-160`).
- **Blocked test case:** "A request rejected for curfew offers no check, submit or cancel action" (was TC-UI-012, removed: its expected result came from code only).
- **Related code observation:** `CANCELLABLE` omits `SUBMITTED`, which 02 lists as cancellable (minimal practical impact, since `SUBMITTED` is never at rest), and the Cancel button shows for any `APPROVED` request with no client-side 2-hour deadline check.

## 2. What time zone is "zone-local time"? (01, 06 §1.4)

- **Gap:** [06 — Business Rules §1.4](https://dragan1925.atlassian.net/wiki/spaces/SD1/pages/491521) and 01 › Time handling say curfews are defined in zone-local time, but no page names the time zone of any zone.
- **Code today:** `Europe/Kyiv` for every zone, with a comment that no document states it (`../skypermit/lib/curfew.ts:1-7`).
- **Affected test cases:** all SKY-1 UI cases rely on precondition "browser time zone = Europe/Kyiv"; TC-UI-009 (05:01 start) was marked NOTHING FOUND partly for this reason.

## 3. Are the curfew endpoints inside the curfew? (06 §1.4)

- **Gap:** 06 §1.4 says "no part of the window may fall inside the curfew … evaluated minute-by-minute", but not whether a window ending exactly at 23:00 or starting exactly at 05:00 touches the `KBP-CTR-3` curfew (23:00–05:00).
- **Not written:** on-point boundary cases (window ends 23:00; window starts 05:00). Only off-points ±1 minute were covered (TC-UI-006…009).

## 4. Operator-portal page routes are not documented (04)

- **Gap:** 04 gives only `/login` and `/register`; the request creation form, "My requests" list and detail view have no route in the docs. Code: `/operator/requests/new`, `/operator/requests`, `/operator/requests/<id>`.
- **Effect:** test cases now describe the page in plain words ("open the request creation form") instead of citing a path.

## 5. What does `validate` return when a gate fails? (03)

- **Gap:** [03 — API Contract › Flight requests](https://dragan1925.atlassian.net/wiki/spaces/SD1/pages/65822) says endpoint 13 "runs every gate exactly as `submit` would … and never changes state", but never states its status code or body on failure. `422` is only implied by the general Error semantics table.
- **Possible conflict:** 04 promises "a per-gate pass/fail result" for "Check before submitting" and "all four gate results" on the reviewer detail view, which 03 says comes from `validate`. A first-failure `422` body (one gate) can't carry four independent results.
- **Code today:** `validate` stops at the first failure and returns `422` with `failing_gate`/`rule_reference`/`message` (`../skypermit/app/api/v1/flight-requests/[id]/validate/route.ts:37-43`, `../skypermit/lib/http.ts:34-41`); the UI infers PASS for earlier gates and "not evaluated" for later ones (`../skypermit/components/GateResultsPanel.tsx:9-21`).
- **Affected test cases:** TC-UI-003, 007, 008, 010 (network check on `validate`). Verifiers split: 003/007/008 accepted `422` as inferred; 010 returned NOTHING FOUND IN DOCUMENTATION.

## 6. Which gate owns the overlap check? (02 vs 06)

- **Conflict:** [02 — State Machine](https://dragan1925.atlassian.net/wiki/spaces/SD1/pages/131074) says the overlap check sits "inside the `AIRCRAFT` / `TIME_WINDOW` gates"; [06 §1.4](https://dragan1925.atlassian.net/wiki/spaces/SD1/pages/491521) and §6 place it only under `TIME_WINDOW` (`TSD-4 §5`). Not settled by 07.
- **Effect:** no SKY-1 case depends on it; any future overlap case must pick a gate.
